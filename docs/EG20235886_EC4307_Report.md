## Abstract

SkillSwap is a full-stack web application developed using the MERN (MongoDB, Express.js, React, Node.js) stack. The platform enables university students to exchange skills with each other — teaching what they know and learning what they don't, without monetary transactions. Key features include dual authentication (email/password and Google OAuth 2.0), a bidirectional skill matching algorithm, session booking workflow, real-time messaging via Socket.IO, gamification through points and achievements, and a community Study Hub for sharing learning resources. The application implements complete CRUD operations backed by MongoDB, JWT-based session management, and a responsive design with dark/light theme support. This report describes the system design, implementation, testing, and results of the project.

**Keywords:** MERN Stack, Skill Exchange, OAuth 2.0, Socket.IO, MongoDB, JWT

## 1. Introduction

### 1.1 Problem Statement

University students frequently need to learn new skills to enhance their academic and professional profiles. However, formal courses are expensive, and students often lack access to affordable learning opportunities. Simultaneously, many students possess valuable skills they could teach but lack a structured platform to offer them.

### 1.2 Objectives

The primary objectives of SkillSwap are:

1. **Facilitate peer-to-peer learning** — Enable students to teach and learn from each other without monetary transactions.
2. **Smart matching** — Connect students whose skills complement each other's learning goals.
3. **Session management** — Provide booking, scheduling, and reviewing capabilities.
4. **Real-time communication** — Allow instant messaging between matched students.
5. **Gamification** — Encourage participation through points, achievements, and leaderboards.
6. **Resource sharing** — Offer a community-driven study material library.

### 1.3 Scope

The system is designed for university students and includes user authentication, skill management, matching, session booking, reviews, notifications, real-time chat, achievements, and a Study Hub. It does not include payment processing, video calling, or mobile applications in this version.

## 4. Database Design

### 4.1 Collections

SkillSwap uses **7 MongoDB collections**:

1. **Users** — Authentication, profile, skills, points
2. **Skills** — User skill posts (Offer/Request)
3. **Sessions** — Learning session bookings
4. **Reviews** — Post-session ratings
5. **Messages** — Real-time chat
6. **Notifications** — User activity alerts
7. **Resources** — Study Hub file uploads

### 4.2 Schema — User Collection

```javascript
{
  name: String (required),
  email: String (unique, required),
  password: String (hashed),
  googleId: String,
  authProvider: 'local' | 'google',
  avatar: String,
  university: String,
  skillsOffered: [String],
  skillsWanted: [String],
  points: Number (default: 0),
  timestamps: true
}
```

### 4.3 Schema — Session Collection

```javascript
{
  requester: ObjectId → User,
  mentor: ObjectId → User,
  skill: String,
  date: String,
  time: String,
  mode: 'Online' | 'Physical',
  status: 'Pending' | 'Accepted' | 'Rejected' | 'Completed' | 'Cancelled',
  message: String,
  timestamps: true
}
```

### 4.4 Entity Relationships

- **User → Skills** (1:N)
- **User → Sessions** (requester/mentor: 1:N)
- **Session → Review** (1:1)
- **User → Messages** (sender/receiver: 1:N)
- **User → Notifications** (1:N)
- **User → Resources** (1:N)

### 5.2 Authentication Flow

1. User submits credentials (or Google OAuth token)
2. Server validates and generates JWT via `jsonwebtoken`
3. JWT returned to client, stored in `localStorage`
4. Client includes JWT in `Authorization: Bearer <token>` header
5. `protect` middleware verifies JWT and attaches `req.user`

### 5.3 Matching Algorithm

```javascript
const matches = allUsers.map(otherUser => {
  const theyCanTeachMe = otherUser.skillsOffered.filter(skill => 
    currentUser.skillsWanted.includes(skill.toLowerCase())
  );
  const iCanTeachThem = currentUser.skillsOffered.filter(skill => 
    otherUser.skillsWanted.includes(skill.toLowerCase())
  );
  
  const isPerfectMatch = theyCanTeachMe.length > 0 && iCanTeachThem.length > 0;
  const totalMatched = theyCanTeachMe.length + iCanTeachThem.length;
  
  let score = 0;
  if (isPerfectMatch) score = Math.min(100, 60 + totalMatched * 15);
  else if (totalMatched > 0) score = Math.min(50, totalMatched * 20);
  
  return { user: otherUser, theyCanTeachMe, iCanTeachThem, isPerfectMatch, matchScore: score };
}).filter(m => m.matchScore > 0).sort((a, b) => b.matchScore - a.matchScore);
```

### 5.4 Real-time Messaging

Socket.IO server maintains a `Map<userId, socketId>`. When a user comes online, their ID maps to the socket. Messages are emitted directly to the recipient's socket for instant delivery. Typing indicators and online status are broadcast similarly.
